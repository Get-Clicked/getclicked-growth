## When Results Are Not OK -- How to Write This Page

When a scraper returns a non-ok status, surface it explicitly. Never silently omit. Always tell the user what to do next.

**Meta: `not_found`**
> "We searched Facebook Pages for Bloom's handle and didn't find a verified match. Either the Page uses a different handle than the website (check `facebook.com/<handle>` manually) or the business has no Facebook Page. Re-run with the exact Page URL if you have one."

**Meta: `consent_or_login_wall`**
> "Meta Ad Library blocked the anonymous scrape behind a login wall today. Debug screenshot saved to `.live-ads-debug/`. Rerun in an hour -- this is usually transient. If it persists, Meta's anonymous access may be tightening and we'll need to document the block in `/context` rather than retry."

**Meta: `no_ads`**
> "Bloom's Facebook Page exists (`page_id: 104558392817`) but no ads are currently active on Meta. This is legitimate -- not every brand advertises on Meta. Skip the Meta section in downstream creative planning; Google is Bloom's active paid channel."

**Meta: `selector_break`**
> "Meta's Ad Library DOM changed and our card selectors no longer match. Debug screenshot saved to `.live-ads-debug/`. This blocks the Meta inventory until selectors are refreshed -- file a Linear issue with the screenshot and proceed with Google data only for now."

**Meta: `timeout`**
> "Meta Ad Library didn't respond in time. Sometimes the grid lazy-loads slowly when a Page has dozens of ads. Retry once; if it times out again, cap at partial results and note in `/context` that the Meta inventory is incomplete."

**Google: `unverified_advertiser`**
> "No verified advertiser record exists for `trybloom.io` in Google Ads Transparency Center. Google only surfaces ads from advertisers who've completed identity verification, which smaller businesses often haven't. This doesn't mean Bloom isn't advertising -- it means the Transparency Center won't show it. If Google Ads is connected, pull `google_ads_ad_performance` for actual campaign data."

**Google: `ambiguous`**
> "Multiple verified advertisers matched `trybloom.io`. Candidates returned: Bloom Inc. (`AR17482938201`), Bloom Marketing LLC (`AR20938475020`). Which is the client? Re-run with the exact `advertiser_id` once confirmed, or confirm in the `/context` flow so we can lock it into `context/live-ads.json`."

**Google: `selector_break`**
> "Google Transparency Center's DOM changed and our grid selectors no longer match. Debug screenshot saved to `.live-ads-debug/`. Same as the Meta case: file a Linear issue with the screenshot and fall back to Meta-only inventory for this run."

**Google: `consent_or_login_wall` or `rate_limit`**
> "Google Transparency Center blocked the scrape -- either a consent banner we don't dismiss or a rate-limit flag. Debug screenshot saved to `.live-ads-debug/`. Wait 30 minutes and retry. If it keeps failing on the same advertiser, note it in `context/live-ads.json` with the status code and move on."

## Notion Mirror (what the skill writes)

When `context/notion-workspace.json` has a `pages.live_ads` entry, the skill writes TWO artifacts to Notion alongside the local `live-ads.md`:

**1. Narrative page** — `Live Ads Inventory` under the Research section. Content is the narrative above (What's Running + per-platform sections + Channel Gaps + What This Means for /ads). Narrative replaces each run so the page always reflects the latest scrape.

**2. Child database** — embedded under the narrative page. One row per ad. First run creates the database; later runs insert rows against the saved `database_id`. Schema:

| Property | Type | Example value |
|---|---|---|
| Title | title | `Bloom Video 789012` |
| Platform | select | `Meta` |
| Advertiser | rich_text | `Bloom` |
| Format | select | `Video` |
| Status | select | `Active` |
| Start Date | date | `2026-03-15` |
| Source | select | `page_scoped` |
| Creative Text | rich_text | `Skip the onboarding paperwork. Bloom ships in 48 hours.` |
| Media | url | `https://scontent.xx.fbcdn.net/v/t42.9040-2/...mp4` |
| Link | url | `https://www.facebook.com/ads/library/?id=...789012` |
| Scraped | date | `2026-04-19` |

The `Source` column tags where each ad came from -- `page_scoped` (Meta Page Ad Library), `keyword_fallback` (Meta keyword search; brands running via Business Manager land here), `domain_suggestion` (Google domain-level match when no direct advertiser exists). This matters for confidence: `page_scoped` is the advertiser's own Page ads (high confidence); `keyword_fallback` is name-matched from a broader search (medium); `domain_suggestion` is the shared-domain view (medium-high, but may include multiple advertiser accounts).

Filters the skill user actually wants once the database exists: "show me only video ads," "show me only ads that started this month," "show me Meta-only," "show me ads with a Media URL so I can review the creative." All cheap with the database; impossible with a flat markdown page.
